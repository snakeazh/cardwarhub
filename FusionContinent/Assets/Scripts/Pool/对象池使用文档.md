# 对象池使用文档

## 1. 当前对象池体系

项目当前有 3 类对象池管理器：

- `UIPanelItemPoolManager`
  - 用于 UI 面板级节点、通用 UI 动态项
- `CommonItemPoolManager`
  - 用于公共对象，如 `RewardEntity`、`BackPackItem`、`CombatTip`
- `BatttleItemPoolManager`
  - 用于战斗内对象

它们都继承自 `BaseItemPoolManager`，核心能力一致：

- 按 `poolKey` 创建对象池
- 同步/异步获取对象池
- 预定义池配置
- 预加载 prefab
- 预热实例
- 统一归还 / 销毁

---

## 2. 常用接口说明

### 2.1 `GetGameObjectPool(string poolKey)`

**只获取已经存在的对象池，不会自动创建。**

```csharp
var pool = CommonItemPoolManager.Instance.GetGameObjectPool("CombatTip");
```

适用场景：

- 你能确定该池已经创建完成
- 只是想读已有池，不希望隐式创建

注意：

- 如果池还没创建，返回 `null`
- 这是很多“为什么找不到对象池”的直接原因

---

### 2.2 `GetGameObjectPoolOrCreate(string poolKey, Transform parent = null, int maxCount = 120, bool worldPositionStays = false)`

**优先获取现有池；如果没有，则自动加载 prefab 并创建对象池。**

```csharp
var pool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("RewardEntity");
var obj = pool?.Get();
```

适用场景：

- 大多数业务代码
- 不确定池是否已经初始化完成
- 希望首次使用时自动创建

推荐：

- 非特殊场景，优先使用这个接口

---

### 2.3 `CreateGameObjectPool(string poolKey, GameObject prefab, Transform parent = null, int maxCount = 120, bool worldPositionStays = false)`

**使用指定 prefab 显式创建对象池。**

```csharp
var pool = CommonItemPoolManager.Instance.CreateGameObjectPool(
    "GeneralCardSlot",
    itemPrefab.gameObject
);
```

适用场景：

- prefab 不是通过资源名直接加载，而是运行时从现有模板节点建池
- 例如 ScrollView 的 item 模板节点

---

### 2.4 `pool.Get(...)`

从对象池中取出一个实例。

```csharp
var obj = pool.Get(parent);
```

常见写法：

```csharp
var rewardPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("RewardEntity");
var rewardObj = rewardPool?.Get(targetParent);
```

---

### 2.5 `pool.Return(obj)`

将实例归还对象池。

```csharp
pool.Return(rewardObj);
```

注意：

- 归还时尽量确保对象确实属于该池
- 如果对象中挂了额外池化子节点，先归还子节点，再归还父节点

---

## 3. 预定义池

对象池管理器可通过 `BuildDefaultPoolConfigs()` 配置预定义池。

当前示例：

### 3.1 `CommonItemPoolManager`

当前默认包含：

- `RewardEntity`
- `ShopItemTitleObj`
- `BackPackItem`
- `CombatTip`

### 3.2 `UIPanelItemPoolManager`

当前默认包含：

- `CardGroupSlot`
- `SoldierCardGroupSlot`
- `ConfirmDialogPanel`
- `ShopItemTitleObj`

### 3.3 `BatttleItemPoolManager`

当前默认包含：

- `coin`

并支持运行时追加：

```csharp
BatttleItemPoolManager.Instance.AddBattlePool("FireBall");
BatttleItemPoolManager.Instance.AddBattlePools(skillEffectNames);
```

---

## 4. 推荐使用规则

## 4.1 普通公共对象

例如：

- `RewardEntity`
- `CombatTip`
- 背包 item

推荐：

```csharp
var pool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("RewardEntity");
var obj = pool?.Get();
```

不要写成：

```csharp
var obj = CommonItemPoolManager.Instance.GetGameObjectPool("RewardEntity")?.Get();
```

因为如果池还没创建，这里会直接拿到 `null`。

---

## 4.2 战斗内对象

例如：

- 投射物
- 战斗特效
- 战斗技能生成物

推荐使用：

```csharp
var pool = BatttleItemPoolManager.Instance.GetGameObjectPoolOrCreate(poolKey);
var obj = pool?.Get(parent);
```

不要再放到 `CommonItemPoolManager`。

---

## 4.3 UI 面板内动态节点

如果是 **UIFramework 的 `UIPanel`**，优先用 `UIPoolScope` 管理生命周期。

推荐流程：

1. 从某个对象池管理器取对象
2. 使用 `PoolScope.Track(...)` 登记
3. 在 `OnHide` / `OnClose` / 切换数据源时通过 `PoolScope.ReleaseGroup(...)` 或 `ReleaseAll()` 释放

示例：

```csharp
private const string ConsumeMaterialGroup = "AwakeningConsumeMaterials";

var rewardPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("RewardEntity");
var rewardObj = rewardPool?.Get(parent);
if (rewardObj != null)
{
    PoolScope.Track(rewardPool, rewardObj, ConsumeMaterialGroup);
}
```

释放：

```csharp
PoolScope.ReleaseGroup(ConsumeMaterialGroup);
```

适用场景：

- `AwakeningPanelNew`
- `ProbabilityDescPanelNew`
- `NormalShopList01New`
- 其他 `UIPanel<TViewModel>` 动态节点

---

## 4.4 ScrollView item

如果 ScrollView 支持：

- `SetPrefabFactory(...)`
- `SetReleaseAction(...)`

应明确把 item 的创建 / 释放接入对象池。

推荐模式：

```csharp
scrollView.SetPrefabFactory(CreateItemNode);
scrollView.SetReleaseAction(ReleaseItemNode);
```

示例：

```csharp
private GameObject CreateItemNode(RectTransform parent)
{
    var itemPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("BackPackItem");
    var item = itemPool?.Get(parent)?.GetComponent<ScrollItem>();
    if (item == null)
    {
        return null;
    }

    item.OnSpawn();
    return item.gameObject;
}

private void ReleaseItemNode(GameObject obj)
{
    if (obj == null)
    {
        return;
    }

    obj.GetComponent<ScrollItem>()?.OnRelease();
    var itemPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("BackPackItem");
    itemPool?.Return(obj);
}
```

注意：

- item 本体是什么节点，就按那个节点建池
- 不要只写 `ShowList(...)`，却没指定 item 创建来源
- 如果 item 内还有池化子节点，先回收子节点，再回收 item 本体

## 5. `UIPoolScope` 使用说明

`UIPoolScope` 用于把“从池里拿出来的对象”挂到某个 UI 生命周期上统一管理。

### 5.1 获取方式

`UIPanel` 已经内置：

```csharp
protected UIPoolScope PoolScope => mPoolScope ??= EnsurePoolScope();
```

所以在 `UIPanel` 子类里可以直接使用：

```csharp
PoolScope.Track(pool, instance, "groupName");
```

### 5.2 常用接口

#### `Track(pool, instance, group)`
记录某个对象属于哪个组。

#### `ReleaseGroup(group)`
释放某个分组的所有对象。

#### `ReleaseAll()`
释放当前面板通过 `PoolScope` 跟踪的所有对象。

### 5.3 适用原则

适合：

- 动态奖励节点
- 面板内临时图标
- 临时 UI 特效
- 一次打开面板后生成的一批对象

不适合直接替代：

- 常驻节点
- 非池化普通 `Instantiate` 对象
- 完全由 ScrollView 自己内部缓存管理的节点（除非你已经接管创建/释放）

## 6. 常见问题

### 6.1 为什么 `GetGameObjectPool("CombatTip")` 返回空？

原因：

- `GetGameObjectPool(...)` 只获取已存在池，不会自动创建

正确写法：

```csharp
combatTip = CommonItemPoolManager.Instance
    .GetGameObjectPoolOrCreate("CombatTip")
    ?.Get()
    ?.transform;
```

---

### 6.2 预定义池已经配置了，为什么还是拿不到？

因为“预定义”只代表：

- 配置里声明过这个池
- 支持预加载 / 预热 / 自动创建

不代表：

- 当前这一刻对象池一定已经存在于 `mPools` 中

所以仍然建议优先使用：

```csharp
GetGameObjectPoolOrCreate(...)
```

---

### 6.3 什么时候应该手动 `CreateGameObjectPool(...)`？

当 prefab 不是按资源名直接加载，而是运行时模板节点时。

例如：

- ScrollView 的 `ItemPrefab`
- 旧 Panel 上现成挂好的模板节点

---

### 6.4 什么时候应该先回收子节点再回收父节点？

当父节点内部挂了额外池化对象时，例如：

- 卡槽节点里挂了品质特效
- item 节点里挂了 `RewardEntity`

顺序建议：

1. 回收池化子节点
2. 执行 `OnRelease()`
3. 再把父节点 `Return(...)`

---

## 7. 推荐代码模板

## 7.1 普通取用模板

```csharp
var pool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate(poolKey);
var obj = pool?.Get(parent);
if (obj == null)
{
    return;
}
```

---

## 7.2 `UIPanel + PoolScope` 模板

```csharp
private const string RewardGroup = "RewardGroup";

private void RefreshRewards()
{
    PoolScope.ReleaseGroup(RewardGroup);

    var rewardPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate("RewardEntity");
    if (rewardPool == null)
    {
        return;
    }

    var rewardObj = rewardPool.Get(targetParent);
    if (rewardObj == null)
    {
        return;
    }

    PoolScope.Track(rewardPool, rewardObj, RewardGroup);
    rewardObj.transform.SetParent(targetParent, false);
}

protected override void OnHide()
{
    PoolScope.ReleaseGroup(RewardGroup);
}
```

---

## 7.3 ScrollView item 模板

```csharp
private GameObject CreateItemNode(RectTransform parent)
{
    var itemPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate(ItemPoolKey);
    var item = itemPool?.Get(parent)?.GetComponent<ScrollItem>();
    if (item == null)
    {
        return null;
    }

    item.OnSpawn();
    return item.gameObject;
}

private void ReleaseItemNode(GameObject obj)
{
    if (obj == null)
    {
        return;
    }

    obj.GetComponent<ScrollItem>()?.OnRelease();
    var itemPool = CommonItemPoolManager.Instance.GetGameObjectPoolOrCreate(ItemPoolKey);
    itemPool?.Return(obj);
}
```

## 8. 当前建议

1. **默认优先使用 `GetGameObjectPoolOrCreate(...)`**
2. **UIFramework 面板内动态节点优先走 `PoolScope`**
3. **ScrollView item 必须显式指定 `SetPrefabFactory / SetReleaseAction`**
4. **战斗对象统一使用 `BatttleItemPoolManager`**
5. **公共对象继续使用 `CommonItemPoolManager`**
6. **回收顺序遵循：子节点先回，父节点后回**
