## 关键拦截点改动

- `WebDataFun.SendProtoPostRequest`：函数体替换为 `LocalApi.Dispatch`，响应后处理（code 检查/服务器时间/解包）保持不变，调用方零改动；旧 `SendPostRequest`（旧登录面板 JSON 通道）已随旧面板删除；阶段 5 移除 notices 消费分支（`NoticesManager` 已删，任务进度走 `ResultItems.TaskDetails`）。
- `Global.cs`：新增 `Global.LocalServer`（会话上下文）与 `Global.LocalApi`（分发器）；阶段 5 删除 `Global.Token`（单机 token 恒为 `LoginResponse.Token = "local"`，只存于 LoginService.CurrentToken）。
- 网络层已删除：`Assets/Scripts/NetWork/`（WebSocket 客户端/帧编解码/NetWorkManager）整目录移除；登录后不再连网关（原 `LoginService.WaitWebSocket` 心跳/重连删除），`UserModel.LogOut` 不再断 WebSocket，`GameStartMono` 不再实例化 NetWorkManager。
- 登录页已无选服：`LoginService` 的 GetServerList/SelectServer 已删除（阶段 A）。

## 架构要点（切片验证的假设）

1. `WebDataFun` 拦截对全部 107 个调用点零改动。
2. 权威存档 = 内存 `Cardwar.PlayerArchive` proto + `User`，Handler 直接读写；`Global.*` 仍由 `ArchiveModel.ApplyPlayerArchive` / `Items.Update` 回流，UI 层不动。
3. 存档整档序列化为单个 JSON 文件（User + PlayerArchive，`JsonFormatter`），脏标记作"有改动"开关，Flush 全量覆盖写；微信走 `WXFileSystemManager` 直写 `wx.env.USER_DATA_PATH` 绕过 MEMFS，Editor/Android 走 System.IO + .tmp 原子替换。
4. Go 事务/行锁/errgroup 不迁移，同步顺序执行；业务错误以 `LocalServerException` 复刻 Go panic 文案。

## 已知偏差（相对 Go 服务端）

- 天赋懒补齐用 TalentId 比较（Go 端用自增主键比较是已知 bug，按意图修正并注释）。
- Go 事务 err 分支的改写文案不可达（panic 回滚后 re-panic 原文案），本地 Handler 一律让内层原文案上抛。
- 战力 8 Provider 已补齐（equip/equip_slot/hero_seat/speaker/weapon/soldier/skill/talent）；resonance 随共鸣系统移除。
- 驿站 LastClaimTime 并入 `PlayerResource.station_last_claim_time`（proto 新增字段 4，Go 端是独立 player_stamina 表）。
- 任务每日刷新时间存入 `PlayerArchive.task_daily_last_refresh_time`（login.proto 新增字段 48，unix 秒；Go 端是 player_task.last_refresh_time 字段）。
- 任务进度/状态变更不走 Go 的 GeneralParam/notices 推送，统一累积为 TaskEngine.pendingChanges，由 ItemEntrance.Execute 收尾填入 `ResultItems.TaskDetails`（field 16，客户端 PlayerItemModel 已消费并刷红点）；登录则靠全量 Archive 下发。
- 任务日刷新沿用 Go 的自然日口径（utils.TimeToDate，本地时区），与 DailyResetRunner 的 5 点重置点口径并存（同 Go 现状）。
- 任务领奖/活跃领奖路径 Go 不显式触发 TryRefreshDaily（靠 Redis 缓存懒加载），本地为保证跨天状态正确在领取前补刷。
- 存档 Tasks 是 main+daily 合并 map，Go 端 daily 整段 JSON 替换会顺带清掉已从配置删除的每日任务 key，本地无法辨别其类型而残留（无害）。
- 新档当日「每日登录」进度与 Go 一样 +2（user.go:139 建档一次 + DailyResetData 强制重置一次），保留 Go 原口径。
- `TaskEngine.SetProgress` 对 Daily/ChapterAchievements 之外的组类型（Weekly/PvPTicket 等）改为 LogWarning + 跳过，不复刻 Go 的 panic「任务类型未定义」：Go 的 weekly 整体是死代码、线上扁平配置不含其他组类型故 panic 不可达，而新版分组配置里周任务（如 2001 消耗体力）会匹配 TargetType，照搬 panic 会导致战斗开始等扣体力请求整个 500（冒烟测试发现，回归用例 Case7b 覆盖）。
- 冒烟验证已自动化：`Assets/HotFixEditor/LocalServerSmokeTest.cs`（菜单 Tools/LocalServer冒烟测试，或 batchmode -executeMethod FusionContinent.HotFixEditor.LocalServerSmokeTest.Run），16 用例覆盖建档（含全量战力刷新）/任务/天赋升级/领奖/读档/整档落盘/旧存档缺 field 48 字段兼容/同日重登不触发每日重置/英灵升级同步技能等级/老档技能登录迁移/门票登录懒更新与过期重置。
